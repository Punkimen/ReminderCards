# Миграции базы данных

Эти SQL-миграции относятся к серверу на Go и применяются отдельно от запуска
приложения. Они не используют Prisma-миграции бота.

`001_create_decks.sql` предполагает, что таблица `cards` уже существует и имеет
целочисленный первичный ключ `id`, совместимый с `deck_cards.card_id` (`BIGINT`).
Миграция дополняет существующую схему и не создаёт полную схему в пустой базе.

Чтобы применить миграцию один раз, выполните из `server/` команду, предварительно
задав переменную окружения `DATABASE_URL`:

```sh
psql "$DATABASE_URL" -X -v ON_ERROR_STOP=1 -f migrations/001_create_decks.sql
```

Файл выполняется в транзакции. Эта команда не ведёт учёт применённых миграций,
поэтому повторно запускать ту же миграцию не нужно. Для автоматизации развёртывания
используйте инструмент миграций, который сохраняет список применённых версий.

Миграция создаёт таблицы `decks` и `deck_cards`:

- Карточка может не входить ни в одну колоду или входить в несколько.
  «Избранное» может быть обычной колодой.
- Первичный ключ `(deck_id, card_id)` запрещает повторные связи и создаёт индекс
  для поиска карточек колоды.
- Индекс по `card_id` помогает находить колоды карточки и удалять её связи.
- Удаление колоды удаляет её связи, сохраняя карточки. Удаление карточки удаляет
  её связи, сохраняя колоды.
- Существующие карточки не изменяются. Начальные колоды и связи не создаются.

Код репозитория может заполнять `model.Deck.CardIDs` данными из `deck_cards`.
Поля Go-структур сами по себе не загружают связи и не создают столбцы в SQL.

Для получения карточек колоды передайте её ID в параметре `$1`:

```sql
SELECT c.id, c.created_at, c.question, c.answer, c.description
FROM deck_cards AS dc
JOIN cards AS c ON c.id = dc.card_id
WHERE dc.deck_id = $1
ORDER BY c.created_at DESC, c.id DESC;
```
